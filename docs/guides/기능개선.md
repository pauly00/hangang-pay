# 한강페이 기능 개선 가이드

## 목적

한강페이의 사용자 경험, 초기 로딩 성능, 서버 간 인증 안정성을 높이기 위한 고도화 작업을 정리한다. 주요 범위는 프론트엔드 라우트별 코드 스플리팅, QR 스캔 라이브러리 지연 로딩, 정적 자산 최적화, bank 서버 인증, BE에서 bank 서버 호출 시 인증 헤더 자동 부착이다.

## 1. 프론트엔드 코드 스플리팅

### 목표

- `hangang-pay-fe/src/app/router.tsx`에서 페이지 컴포넌트를 앱 시작 시점에 모두 로드하지 않고, 해당 라우트 진입 시점에 로드한다.
- 사용자 역할, 가맹점 역할, 결제/충전/환불 흐름별로 실제 필요한 화면만 다운로드되도록 청크를 분리한다.
- 라우트 이동 중에는 공통 로딩 UI 또는 스피너를 표시한다.

### 작업 항목

- `React.lazy` 또는 라우터의 lazy route 기능을 사용해 페이지 컴포넌트를 동적 import로 전환한다.
- 공통 `Suspense` fallback 컴포넌트를 추가한다.
- 로딩 UI는 기존 디자인 시스템과 맞는 전역 스피너 또는 페이지 로딩 컴포넌트로 구성한다.
- 사용자 전용 페이지, 가맹점 전용 페이지, 인증/회원가입 페이지, 결제/충전/환불 페이지를 청크 단위로 묶는다.
- 라우트 guard가 적용된 페이지도 lazy loading 이후 정상 동작하는지 확인한다.

### 권장 분리 단위

- `auth`: 로그인, 회원가입, 본인/계좌 인증, 약관, PIN 등록
- `user`: 사용자 홈, 사용자 마이페이지, 사용자 거래 내역
- `merchant`: 가맹점 홈, 가맹점 QR, 결제 내역, 정산, 가맹점 마이페이지
- `payment`: QR 스캔, 결제 금액 입력, 결제 확인, 처리/완료 화면
- `charge`: 충전 금액 입력, 충전 처리/완료 화면
- `refund` 또는 `exchange`: 환불/환전 확인, 처리/완료 화면

### 완료 기준

- 초기 번들에서 모든 페이지 컴포넌트가 한 번에 포함되지 않는다.
- 각 라우트 진입 시 해당 페이지 청크가 네트워크에서 로드된다.
- 느린 네트워크 환경에서도 라우트 전환 중 빈 화면이 아니라 스피너가 표시된다.
- 사용자/가맹점 권한 guard 동작이 기존과 동일하다.

## 2. QR 스캔 라이브러리 지연 로딩

### 목표

- QR 스캔 화면에 진입할 때만 QR 스캔 라이브러리를 로드한다.
- 일반 홈, 내역, 마이페이지, 결제 외 화면에서는 스캔 라이브러리가 초기 번들에 포함되지 않도록 한다.

### 작업 항목

- `UserPayScanPage` 또는 QR 스캔 컴포넌트 내부에서 스캔 라이브러리를 동적 import로 전환한다.
- 카메라 권한 요청은 QR 스캔 화면 진입 후 사용자 액션 또는 화면 마운트 시점에만 발생하도록 유지한다.
- QR 스캔 라이브러리 로딩 중 전용 스피너 또는 카메라 준비 상태 UI를 표시한다.
- QR 스캔 실패, 권한 거부, 카메라 미지원 상태의 fallback UI를 확인한다.

### 완료 기준

- QR 스캔 라우트에 진입하기 전에는 QR 관련 라이브러리 청크가 로드되지 않는다.
- QR 스캔 화면 진입 후 라이브러리 청크와 카메라 권한 요청이 정상 처리된다.
- 권한 거부/미지원 환경에서도 화면이 깨지지 않는다.

## 3. 빌드 청크 및 캐시 최적화

### 목표

- Vite 빌드 설정에서 변경 빈도가 낮은 외부 라이브러리를 별도 청크로 분리해 브라우저 캐시 효율을 높인다.
- React, TanStack Query, 상태관리, QR 라이브러리를 개별 vendor 청크로 분리한다.

### 작업 항목

- `hangang-pay-fe/vite.config.ts`의 Rollup `manualChunks` 설정을 추가 또는 보완한다.
- 권장 청크:
  - `vendor-react`: `react`, `react-dom`, `react-router-dom`
  - `vendor-query`: `@tanstack/react-query`
  - `vendor-state`: Zustand 등 현재 사용하는 상태관리 라이브러리
  - `vendor-qr`: QR 생성/스캔 관련 라이브러리
- 빌드 산출물 크기와 청크 분리 결과를 확인한다.
- 라우트 lazy loading과 manual chunks가 충돌하지 않는지 확인한다.

### 완료 기준

- `npm run build`가 성공한다.
- 빌드 결과에서 React, Query, 상태관리, QR 관련 청크가 분리된다.
- 앱 코드 변경 시 vendor 청크 파일명이 불필요하게 바뀌지 않는다.

## 4. 바우처 아이콘 WebP 교체

### 목표

- 기존 바우처 아이콘 이미지 자산을 WebP로 교체해 이미지 용량과 로딩 비용을 줄인다.

### 작업 항목

- 현재 사용 중인 바우처 아이콘 파일 위치와 참조 컴포넌트를 확인한다.
- 동일한 시각 품질을 유지하는 WebP 파일을 추가한다.
- 기존 이미지 import 또는 public path 참조를 WebP로 변경한다.
- 필요하면 기존 PNG/JPG는 호환성 정책에 따라 제거하거나 fallback으로 유지한다.

### 완료 기준

- 바우처 아이콘이 모든 관련 화면에서 정상 표시된다.
- WebP 교체 후 이미지 용량이 감소한다.
- 빌드 및 정적 자산 참조 오류가 없다.

## 5. Bank 서버 요청 인증 필터

### 목표

- `hangang-pay-bank`가 `hangang-pay-be`에서 오는 내부 요청만 처리하도록 `X-Bank-Api-Key` 헤더 기반 인증 필터를 추가한다.
- 헤더값은 `bank.api-key` 환경변수 또는 설정값과 비교한다.
- 비교는 타이밍 공격 가능성을 줄이기 위해 상수시간 비교 방식으로 처리한다.

### 작업 항목

- `hangang-pay-bank`에 `X-Bank-Api-Key` 검증 필터를 추가한다.
- 설정값은 `bank.api-key`로 주입받는다.
- 헤더 누락, 빈 값, 불일치 시 `401 Unauthorized` 또는 프로젝트 표준 에러 응답을 반환한다.
- 아래 경로는 인증 필터 검증에서 제외한다.
  - `/actuator/**`
  - Swagger UI 관련 경로
  - `/v3/api-docs/**` 또는 api-docs 관련 경로
- 필터 등록 순서가 로깅 필터, Spring Security 설정과 충돌하지 않는지 확인한다.

### 테스트 항목

- 올바른 `X-Bank-Api-Key` 헤더가 있으면 요청이 통과한다.
- 헤더가 없으면 차단된다.
- 헤더값이 틀리면 차단된다.
- `/actuator`, Swagger, api-docs 경로는 헤더 없이도 통과한다.
- 동일 길이/다른 길이 입력 모두 상수시간 비교 유틸이 예외 없이 처리된다.

## 6. BE에서 Bank 서버 호출 시 인증 헤더 부착

### 목표

- `hangang-pay-be`가 `hangang-pay-bank`로 보내는 모든 HTTP 요청에 `X-Bank-Api-Key` 헤더를 자동 부착한다.
- 헤더값은 bank 서버와 같은 설정값을 사용한다.

### 작업 항목

- `hangang-pay-be`의 bank client 공통 설정을 확인한다.
- RestClient, WebClient, Feign 등 현재 사용하는 HTTP 클라이언트 방식에 맞춰 공통 interceptor/filter를 추가한다.
- 모든 bank 서버 호출이 공통 클라이언트를 통하도록 정리한다.
- 설정값은 `bank.api-key` 또는 기존 설정 네이밍에 맞춰 주입한다.
- 로컬 개발용 기본값은 bank 서버와 동일하게 맞춘다.

### 테스트 항목

- bank 서버 호출 시 `X-Bank-Api-Key` 헤더가 포함된다.
- 충전, 결제, 환불/환전, 계좌/지갑 생성 등 모든 bank client 메서드가 동일 헤더를 사용한다.
- API key 설정 누락 시 애플리케이션 시작 실패 또는 명확한 설정 오류가 발생한다.

## 7. 컨트랙트 배포 동기화 요청 인증 헤더 추가

### 목표

- bank 서버 인증 필터 추가 이후 컨트랙트 배포 주소 동기화 요청이 차단되지 않도록 인증 헤더를 함께 전송한다.
- 컨트랙트 배포 후 bank 서버로 주소를 저장/동기화하는 흐름을 유지한다.

### 작업 항목

- 컨트랙트 배포 후 bank 서버로 `SaveContractDeploymentsRequest` 또는 관련 요청을 보내는 호출 지점을 확인한다.
- 해당 요청이 공통 bank client를 사용하지 않는다면 공통 헤더 부착 경로로 이동하거나 별도 interceptor를 적용한다.
- 헤더값은 환경변수에서 주입받고, 로컬 개발 기본값은 bank 서버와 동일하게 둔다.

### 테스트 항목

- 컨트랙트 배포 동기화 요청에 `X-Bank-Api-Key` 헤더가 포함된다.
- 인증 필터가 활성화된 bank 서버에서도 배포 동기화 요청이 성공한다.
- 인증 헤더 누락 시 기존 문제를 재현하는 테스트 또는 회귀 테스트가 존재한다.

## 8. 설정값 정리

### 공통 설정

```yaml
bank:
  api-key: ${BANK_API_KEY:local-bank-api-key}
```

### 운영 주의사항

- 운영 환경에서는 `BANK_API_KEY`를 반드시 Secret Manager, CI/CD secret, 서버 환경변수 등으로 주입한다.
- BE와 bank 서버의 `BANK_API_KEY` 값은 동일해야 한다.
- API key는 로그에 남기지 않는다.
- 문서, 테스트 코드, 샘플 설정에는 로컬 개발용 값만 둔다.

## 9. 권장 구현 순서

1. `hangang-pay-bank` 인증 필터와 단위 테스트 추가
2. `hangang-pay-be` bank client 공통 인증 헤더 부착 및 단위 테스트 추가
3. 컨트랙트 배포 동기화 요청 헤더 적용 및 회귀 테스트 추가
4. 프론트엔드 `router.tsx` 페이지 컴포넌트 lazy loading 전환
5. QR 스캔 라이브러리 지연 로딩 적용
6. Vite manual chunks 설정으로 vendor 캐시 최적화
7. 바우처 아이콘 WebP 교체
8. BE/Bank 테스트, FE 빌드, 주요 사용자/가맹점 플로우 수동 검증

## 10. 최종 검증 체크리스트

- `hangang-pay-bank` 필터 테스트 통과
- `hangang-pay-be` bank client 헤더 부착 테스트 통과
- 컨트랙트 배포 동기화 요청 인증 헤더 테스트 통과
- `hangang-pay-fe` 빌드 성공
- 초기 번들에 전체 페이지와 QR 스캔 라이브러리가 포함되지 않음
- 라우트 진입 시 lazy chunk 로딩 및 스피너 표시 확인
- 사용자/가맹점 역할별 접근 제어 기존 동작 유지
- 결제, 충전, 환불/환전 흐름 정상 동작
- 바우처 아이콘 WebP 표시 확인
